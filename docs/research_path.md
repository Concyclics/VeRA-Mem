# Research path: from sparse vector modulation to block-structured memory

This document summarizes the experiments completed through 2026-10-06. It separates the intended research direction from what the measurements establish. Detailed stage reports preserve unsuccessful runs, protocol repairs, and limits; their scores are not a single directly comparable leaderboard.

## Research question

Can a frozen language model acquire and revise usable memories by writing input-derived vectors, without optimizing shared network parameters for each new observation?

Our proposed interface stores low-dimensional keys and values outside the model. A query comes from the actual token input of a VeRA-adapted layer. Retrieved values generate an input-dependent low-rank residual. An offline-trained writer converts an already observed support into new K/V records. Online learning changes these records, while the backbone and shared query/writer/reader remain frozen.

This is a hybrid of a learned parametric interface and externally stored, editable state. We call it writable parameter-vector memory because V controls the layer's effective operator; the online records are not ordinary persistent optimizer-trained model weights. The working goal is continual learning through forward-pass writes, with explicit update, restoration, and interference tests.

## Relationship to other update mechanisms

| Mechanism | Where new information is stored | What to compare fairly |
| --- | --- | --- |
| Gradient-trained LoRA, including this repository's LoRA-bank baseline | Adaptation weights optimized on observations | Offline training, each supervised gradient write, trainable capacity, and retained quality |
| Memory Decoder | A pretrained parametric decoder distilled from retrieval distributions; its predictions combine with the base model | Memory pretraining, domain coverage, inference overhead, and transfer setting |
| Context-conditioned adapter generators such as Doc-to-LoRA | Adapter weights generated by an offline-trained hypernetwork from a new context | Meta-training cost, write encoding, generated capacity, retrieval/editing behavior, and query cost |
| VeRA-Mem | Input-generated K/V records in a persistent store, read through a shared low-rank interface | Offline interface training, encoding and storage per write, retrieval and injection per token, and fact-level edits |

Standard gradient-trained LoRA needs optimization to absorb new training information, but already trained adapters can be reused. Memory Decoder likewise supports reuse across compatible base models without retraining for every query. Its paper describes domain-memory pretraining, not our per-record VDB upsert protocol. Consequently, a blanket claim that either method must be retrained on every inference is incorrect. [Memory Decoder](https://arxiv.org/html/2508.09874v2#S3), [LoRA](https://arxiv.org/abs/2106.09685).

Forward-pass parameter generation also has prior work: Doc-to-LoRA learns to generate an adapter for an unseen context. Our research question concerns sparse, individually editable records and how they modulate VeRA; avoiding online gradients alone is not a novelty claim. [Doc-to-LoRA](https://arxiv.org/abs/2602.15902). The later [Memory Decoder at Scale](https://arxiv.org/abs/2607.27919) is another relevant parametric-memory baseline, not a result reproduced here.

These rows use different data seeds, task difficulty, budgets, and selection rules. They explain decisions, not a causal learning curve. For example, the early single-word 127/128 result cannot be compared numerically with later three-word novel-combination scores.

## Why move from a pooled vector to a complete block?

The early reader already had learned Q/K/V projections and could retrieve several slots. Its bottleneck hypothesis concerned compressing those selected values into **one rank-space modulation vector**, not the absence of QKV notation or necessarily retrieving only one record.

Three-slot writing then gave each observed word span a contextual vector. Group retrieval retained all three rows of the chosen fact, but the first grouped reader still mixed them into one vector before diagonal modulation. Random reassignment of entity/content bindings reduced the usefulness of fixed entity-to-full-answer lookup shortcuts. Neither change alone produced complete unseen-combination answers.

The latest `BlockVeRA` instead generates a dynamic matrix from the retrieved rows. Its additional term can mix rank-space coordinates and retain associations between input/output factors from the same row. The pooled control has the same added parameters. Keeping a matrix-shaped tensor alone would not help if subsequent operations were algebraically equivalent to the old sum; the changed operator is essential.

The current block experiment also changes within-group weights to uniform in all three matched arms. Its diagonal control is trained afresh; it is not the preceding QKV checkpoint. Same-seed addressing parameters are identical across these three readers, but later autoregressive queries can diverge with generated prefixes. [Architecture](architecture.md), [mechanism evidence](block_results.md).

## What we can claim

**Established within the reported settings:**

- Actual layer-input queries drive CPU-vector-store retrieval during generation.
- Observed supports generate writable values; online tests freeze all shared parameters.
- Restricted same-template tasks show useful new-fact writing, with shuffled/empty controls.
- Multi-vector writing and an offline-trainable B can solve seen microtask reconstruction.
- Per-row block operators improve some known-entity unseen-combination results over a parameter-matched pooled reader.

**Still hypotheses or unproven extensions:**

- Excessive sparsity is the dominant cause of failure. The current evidence also implicates binding, content reconstruction, optimization, and format dependence.
- Generalization follows from using QKV or preserving a V matrix. Earlier grouped QKV failed, and the latest block result is limited.
- The benefit comes specifically from rank rather than nonlinear factor construction before pooling or within-row associations.
- Reliable arbitrary-document writing, open vocabulary, long-horizon continual learning, robust paraphrases, and cross-domain deployment.
- Production-scale ANN search, low-latency CPU offload, or superiority over LoRA/Memory Decoder under matched quality and total cost.

The latest gate requires consistent gains across all three seeds, including complete update-and-restore success and memory controls. Only one random-binding seed passed all individual conditions. It is a predeclared progression criterion, not a proof that the architecture has no research value.

## Recommended next investigation

Stay with a small, controlled task while separating three possible sources of benefit:

1. Compare the existing pooled outer product with **mean of separately generated factors**, still rank one. This isolates nonlinear factor construction before pooling.
2. Compare that factor-mean operator with the current mean of matched per-row outer products. Their difference is a factor covariance term.
3. As a diagnostic, permute the pairing of input/output factors while preserving their marginal sets and the selected fact. This tests whether within-row association matters.

These are proposals, not completed results. Use a new protocol and fresh confirmation combinations; the current C/D sets are now observed. Extend entity/query variation and corpus complexity only after complete content preservation and update/restore controls become reliable.
