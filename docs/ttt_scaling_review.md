# TTT、可写记忆与本项目的扩容实验

核对日期：2026-10-05。本文区分原论文证据、对当前失败的解释和待检验设计。它是本轮实验的依据，**不把尚未执行的规模或消融写成已完成结果**；实际结果由对应运行目录、配置与实验报告证明。

## 1. 数据不足很可能存在，但不是唯一解释

本项目上一轮只有 **128 个离线事实、3 个 epoch、384 次答案监督更新**，却要学习约 187 万个共享参数，并让冻结的 Qwen3-4B 解读新的 rank-64 参数化接口。这远小于已发表方法用于训练读写接口的预算。不过，第一版 value 全部相同、联合训练后 key 余弦集中到 0.995，以及正确 value 条件也只能回答 3/32，分别提示优化退化、寻址失稳和读出不足。增加样本不能保证修复这些问题。[本项目原始证据](pilot_results.md)

因此应同时检验两个问题：**更多独立事实是否改善泛化；更合适的初始化和训练接口是否让这些事实变得可学习。** 只把同一数据多跑几轮，或者只往一个未学会读取的 VDB 添加记录，均不能回答前一个问题。

## 2. 原论文究竟训练了什么

表中的离线训练量、测试流长度、测试题数是不同量纲。大规模离线训练后的小规模测试，不是“小样本训练即可产生记忆”。

| 工作与原始来源 | 离线训练和初始化 | 测试时更新 | 对本项目最相关的边界 |
| --- | --- | --- | --- |
| [TTT，v4，§2.7、Table 3、Appendix C](https://arxiv.org/html/2407.04620v4) | 从头训练包含 TTT 层的网络。125M / 350M / 760M / 1.3B 对应 2.5B / 7B / 15B / 26B token；4,800 / 13,500 / 29,000 / 50,000 个外循环 step。每批约 0.5M token。共享初态 `W0` 在外循环学习，论文报告其提高稳定性。 | 每个序列从共享初态开始，对投影后的输入做自监督内循环更新；mini-batch 为 16 token。内循环 base LR：Linear 为 1，MLP 为 0.1，再乘输入相关 sigmoid 门控。 | 学习初态有依据；这些 LR 是特定重建内循环的数值，不能直接用于本项目 Adam writer。主要测试为 Pile/Books LM，context 1k–32k；不是冻结 Qwen 的外挂实验。 |
| [Titans，v1，§3、§5.1–5.4](https://arxiv.org/html/2501.00663v1) | 把神经记忆放进初始架构，端到端训练。170M / 340M / 400M 各 15B FineWeb-Edu token；760M 为 30B。训练长 4k，批量 0.5M token，AdamW LR 4e-4，weight decay 0.1。持久记忆与输入相关快记忆分开。 | 神经记忆通过 key–value 重建梯度更新，带动量、遗忘及输入相关速率；外循环学习投影与整体网络。 | 支持稳定快/慢状态分工，不证明随机外挂即可读取。RULER S-NIAH 的 2k/4k/8k/16k 与 BABILong 长流是不同测试；“超过 2M context”不是离线样本量。 |
| [M+，v2，§3.2.3–3.2.4、§4.3](https://arxiv.org/html/2502.00592v2) | 基于 Llama-3.1-8B，先训练 MemoryLLM 接口 **1,200,000 step / 4 周**。第二阶段四个 4k–64k 长度桶各取 200,000 文档，再与 FineWeb 等权混合，1 epoch；第三阶段用另取文档训练长记忆读取。 | 新文本产生潜空间记忆，丢出短记忆的向量进入 CPU 长记忆；联合训练过的 query/key 投影稀疏取回。 | 不是只训练一个未适配读出层。长期保持评估在 SQuAD/NaturalQA 过滤后各取前 100 题，并插入无关上下文；该 100 是评估题数。论文正文未给出足够信息复原全部阶段 LR，不能猜填。 |
| [Larimar，v4，§2.1–2.2、§5](https://arxiv.org/html/2403.11901v4) | 从预训练 encoder/decoder 初始化后，**encoder、memory、decoder 联合训练**。7.6M 个 64-token 样本；6B 版 10 epoch，Adam LR 5e-6，batch 32，8×A100。训练后的 memory 是 prior `M0`，并有无记忆重建及基座语言建模保持项。 | 通过最小二乘/伪逆进行一次写入与序贯更新，不为每条新事实重新梯度训练模型。 | prior + 读写接口协同训练非常相关；但其 decoder 非始终冻结。CounterFact 单事实测试用前 2,000 例，测试编辑量与离线 7.6M 样本不能混同。 |
| [Doc-to-LoRA，v1，§3、Appendix A/B](https://arxiv.org/html/2602.15902v1) | 冻结目标 LLM，训练从文档激活到 LoRA 的 hypernetwork。简化 NIAH：640k 样本，32–256 token，1 epoch，LR 4e-5，单 H200 约 3h。完整训练数据约 3.2M 独立上下文；先 80k 单 chunk step，再 20k 组合 step，每批累积超过 200k context token / 8 GPU。 | 对新文档前向生成参数，不为该文档重新训练 hypernetwork。 | 最接近“冻结基座也能学新参数接口”的规模参照。作者先学单块读出再学组合；简化 NIAH 使用相同训练/测试问句格式，不能据此证明问法泛化。 |

以上数字是各论文所报告的设置，**不是本项目达到效果的最低所需预算**，也不能跨架构按 token 数作样本复杂度排名。

代码核对补充：

- [TTT 官方仓库](https://github.com/test-time-training/ttt-lm-jax)提供训练脚本与数据准备；表中外循环 peak LR 随模型规模为 3e-3 / 1.5e-3 / 1.25e-3 / 1e-3，不能和内循环 LR 混用。
- [M+ 官方仓库](https://github.com/wangyu-ustc/MemoryLLM)明确把 M+ 训练代码放在单独分支；主分支旧 MemoryLLM YAML 不是所有 M+ 阶段的完整配置。
- [Larimar 官方示例 YAML](https://raw.githubusercontent.com/IBM/larimar/main/larimar_base/configs/config_train_larimar.yaml)是 BERT-base/GPT-2、LR 5e-5、batch 64、4 epoch 的另一设置。不要把它与论文 6B 配置拼成一次实验。
- [D2L 官方实现](https://github.com/SakanaAI/Doc-to-LoRA)释放的是已经训练的 hypernetwork；其权重不能直接当作 Qwen3-4B 的初始化。

## 3. 冷启动必须拆成两种可检验机制

**学习到的初始槽位（learned prior slots）。** 在离线 train episodes 中优化一组 key/value 与 VeRA 读出参数；测试时从同一份固定初态克隆。它提供可用的激活分布和一般读出先验，但没有测试新实体事实。训练出的槽位是共享参数，其字节数和训练量必须计入预算。

**从已观测事实建立的初始库（bootstrapped factual bank）。** 在测试流开始前，将协议允许提供的 support 经过冻结 writer 写成 key/value，例如 256 条 priming 观测。随后加入从未出现的新实体。这提供已有知识，正如用户建议的预填充 VDB。它不能预先包含未来测试问题的答案、未来更新版本或测试生成结果。

两个机制都合理，但测量含义不同。前者主要检验初始化/协同训练，后者主要检验有历史库时的新写入与干扰。冷库上的高 priming 准确率不能单独证明持续学习；需要同时报告新写入前后、旧事实保持和没有写入的事实。

建议最小对照：

| 初态 | 共享 reader/writer | 合法初始事实 | 要回答的问题 |
| --- | --- | --- | --- |
| Empty | 已离线训练 | 0 | 不借助 priming 的新写入能力 |
| Random | 同一 checkpoint | 与冷库同槽数、同 norm 的随机无语义向量 | 有更多向量或非零 residual 本身是否造成改变 |
| Cold | 同一 checkpoint | 256 个 disjoint priming support | 合法预填充是否改善稳定性或仅增加干扰 |
| Learned prior + Cold | 初始化槽位与接口协同训练 | 同一 256 个 support | 学习初态是否优于仅加记录 |

主比较不要求以上四项一次全部重训练。先在同一 checkpoint 上比较 Empty/Random/Cold；学习初态若需要改变结构，另给相同数据/步数训练对照。不能把一方更长训练得到的收益归给冷启动。

## 4. 本轮可实现的样本规模与预算

离线实体集采用嵌套子集 `train_128 ⊂ train_1024 ⊂ train_4096`。开发集、priming、在线新事实、未观测事实和替换模板测试保持完全相同，均与训练实体不重合。生成器先产生 manifest、ID 与 hash，再启动训练。

| 条件 | 不同训练事实 | 每事实平均曝光 | 总训练 episode 曝光 | 用途 |
| --- | ---: | ---: | ---: | --- |
| N128-E3 | 128 | 3 | 384 | 重跑旧预算，隔离结构改变 |
| N1024-E3 | 1,024 | 3 | 3,072 | 中等扩容 |
| N4096-E3 | 4,096 | 3 | 12,288 | 32 倍独立事实 |
| N128-matched | 128 | 96 | 12,288 | 同总曝光但只反复看小集合 |
| N1024-matched | 1,024 | 12 | 12,288 | 固定曝光下的独立数据效应 |

这里列的是 episode 曝光，不保证是 optimizer step。若 effective batch=B，则理想更新数约为曝光/B；应以日志的实际 `optimizer_steps`、有效答案 token 数和总 forward/backward token 数为准。固定 epoch 曲线同时改变数据和计算；只有 matched 组才能进一步区分两者。截断长度变化时还需同时列训练 token 与 GPU 时间。

可以先完成 128 与 1,024 的配对诊断再启动 4,096；保持 4,096 作为本轮明确的规模试验，而不是在小集出现负结果时永远停留在 128。不要直接扩到百万事实后才检查读出。

统一开发与测试建议：开发 256 事实；测试 priming 256、在线新写入 256、从未观测 128；最终同题和替换问法各一次。若运行预算限制需缩减，所有方法统一缩减并在结果中声明。至少先做一个训练种子的机制探索，确定配方后再用三个独立训练种子确认；不能把同一模型的三个数据流 seed 当成三次训练复现。

## 5. 先使 value 有内容，再让稀疏检索承担难度

以下是**本项目的工程假设**，不是上述论文已经证明的 VeRA 改进。

1. **规范化 writer 输入并移除易饱和的无约束链路。** 比较 `tanh(Wv h)` 与训练集统计中心化/尺度归一化后的线性或 RMS-normalized value；给残差单独的小幅可学习缩放。Norm 约束限制振幅，不能替代语义训练。训练统计只由 train support 拟合，并写入 checkpoint。
2. **初始化时让两类梯度都能传播。** 小 residual 可保护基座；但不能同时把 writer 输出、读出 gate 和投影全部置零，否则 writer 收不到梯度。每轮 smoke test 检查 writer、reader、query/key 的梯度范数。
3. **把读出能力与寻址能力分阶段建立。** 先用正确 support 的单条 value 训练 readout，配合 value 重建/蒸馏辅助项，让正确 value 优于置换与零 value；然后逐步加入可检索 distractors，把 oracle 读取替换成真实 top-k。最终推理仍从每个 token 的真实 VeRA 输入得到 query，不能用 oracle 或外部解析器替代主方案。
4. **寻址单独保持判别信号。** 用同实体不同问法为正例、不同实体同答案/同模板为难负例，防止按答案或模板聚类。先做 query/key 对比预训练，再用小 LR 联合训练或暂时冻结；训练中监控检索而不仅 LM loss。离线更新 key encoder 后应重建 bank，禁止让新 query 查询旧坐标版本的 key。
5. **协同训练需要可变 episode。** 在每个训练 episode 内，从 support 写入，再用不同 query 读取；随机构造不同 bank、不同顺序和新旧记录比例。不要给每个训练实体一个永久可优化 value 并把训练集拟合误认为 writer 泛化。
6. **保护原始模型能力。** 加空读/无关 memory 的训练与验证；学到“只输出 16 个常用词”的接口可以降低答案 NLL，却损害一般生成。训练集词表相同而实体随机的实验只能证明受控关联学习，后续需扩大答案词表、多 token 值和关系类型。

首轮优先固定 backbone、插入层和 rank；同时改层数、rank、token 选择、value 归一化和样本量会使结果无法归因。必要的组合修复可以作为新配方整体与旧配方比较，再按收益拆消融，而不是宣称其中每个组件均有效。

## 6. 评估应把四个瓶颈分开

| 维度 | 必报指标 | 诊断意义 |
| --- | --- | --- |
| 写入表征 | value 唯一数、每维 std、有效秩、均值范数、pairwise cosine、最大绝对值；使用 tanh 时额外报饱和率 | 不同值不等于有用值；但相同值或饱和可直接解释失败 |
| 寻址 | 真实 prompt-last-token Recall@1/@k、MRR、top-k权重熵、生成期间证据切换率；逐步增加库大小 | 正确记录进入 top-k 后仍可能被混合稀释 |
| 读出 | 正确 value、真实检索、置换 value、零 residual 的自由生成 EM 与答案 NLL；有限词表候选打分仅作诊断 | oracle 也失败优先查 reader；oracle 成功而检索失败优先查地址/混合 |
| 连续性 | 写入前、立即写入后、后续 32/128/256 次写入后的准确率，priming 保持、冲突更新、未知实体与基座能力 | 对同题重测提升与长期保持分开报告 |

每条事实的执行顺序固定为 `query-before-write → observation → encode/write → query-after-write`。生成过程中只读固定快照；未来 support 不得出现在候选 value、对比负例元数据或 query encoder 的输入。旧事实与新事实在时间线上出现过的 support 可以包含答案；这是合法观测，不是评估标签回流。

对正确/置换/零值条件复用同一事实和 checkpoint，记录各样本预测用于事实级配对 bootstrap。不能仅因 NLL 下降宣称记忆有效；最低证据应包括正确 value 的 EM 超过置换/空读、真实检索改善、并且在未见实体与问法中保留效果。效果不成立也是有效结论，应定位是数据、优化、寻址还是读出限制。

本项目的在线主线仍是**观测产生参数化 value 并写入 VDB**，共享接口冻结。借鉴 TTT 的初始化与外循环训练，并不自动把 append/upsert 变成梯度式 TTT；若以后增加在线 fast-weight 梯度，应单列模式、学习率、优化状态字节数与遗忘对照。
