# Counterfactual context-distillation protocol

This round tests whether a student answers differently and correctly when only one written fact changes under the same question, and preserves the answer when only that fact's wording changes. The previous round showed apple/silver output biases. The main acceptance metric is therefore paired-switch EM, requiring both sides to be correct, rather than a changed output, greater hidden similarity, or one-sided accuracy.

The valid protocol version is `counterfactual-context-v2`. Version v1 incorrectly mixed historical A/P features extracted with a prefix and B features extracted without it; all associated completed runs are retained as invalid records. Version v2 consistently adds the historical fixed prefix `Remember this information: ` before all writer feature extraction, while the teacher still receives the original observation text. New and old features are first checked for agreement on fixed historical training examples; caches, warm-up, and four-arm training are then rerun from the original anchored checkpoint. Losses, budgets, and hyperparameters remain unchanged. The new confirmation set uses seed 37042 and excludes the v1 seed 27042 entities already seen during debugging.

## Fixed data and interventions

Training reuses 4096 historical training entities, 8 question expressions, and 4 observation expressions. Each entity has distinct A/B values. Alternative values are generated by random derangements within answer-token-length groups, preserving each value's marginal frequency on both sides. Different groups do not share a fixed A→B mapping. The actual tokenizer must verify that A/B have different first tokens and equal total teacher-prompt lengths.

Each training batch contains 8 targets, each with its own independent 72-record bank. A target's B bank replaces only its own observation; all other records remain unchanged. Its P bank changes only that A observation to another training expression. The normal writer generates both key and value, so this is the total intervention of updating an observation, not a pure value effect. Actual tensor banks are retrieved independently by batch row. Replacing all eight targets in a shared bank cannot be described as eight single-record interventions.

Training negatives include other entities with the same answers as target A/B; these remain negatives for address classification. Question rendering accesses only the entity. Answers, world labels, and the correct record ID never enter the student prompt or retrieval API. A/B/P forwards use the same parameter snapshot, followed by joint backpropagation and one optimizer update.

The new confirmation set fixes 64 entities with seed 37042, disjoint from historical train/dev/test/control and earlier entity-exclusion sets. JSON and Markdown tables are the two held-out structural families. Each A label and each B label appears once in each of the four combinations of two query styles × two support styles, avoiding answer bias from index-based style assignments. The old development set is not used for model selection. Confirmation and training caches are separate, and formal training loads only train.pt.

Smoke tests use 32 training entities and a small evaluation of 4 of them in training expressions. New confirmation examples are not used to choose the implementation or recipe. Frozen features for the formal caches may be precomputed, but teacher/student behavior on the new confirmation set is measured only after all formal training finishes.

## Shared model and warm-up

The fixed backbone is Qwen3-4B-Instruct-2507, revision `cdbee75f17c01a7cc42f958dc650907174af0554`. Retain layer-20 mlp.down_proj, rank/key dimension 64, top-k 4, temperature 0.05, and frozen random A/B. Initialization uses the historical anchored_all_view checkpoint, without selection on this round's evaluation.

Run 256 shared warm-up updates with batch size 8. Then all four methods start from the same module and Adam optimizer state and receive 512 batch-8 continuation updates. Training fact/negative/view sequences are shared, with seed 42. Warm-up provides 2048 target-pair exposures; continuation provides 4096. Each pair also has A/B/P supervision branches. Use the final step; do not extend training, choose checkpoints, or alter losses based on confirmation results.

Learning rates are 1e-4 for Wv, 0.005 for shared b, and 1e-5 for Wq/Wk. Clip gradient norm to 1 separately for the three parameter groups. Every 4 steps, replay canonical A-world answers for the same targets with weight 0.25. This round differs from the previous one in both data and training volume. Historical scores are background only and do not identify the causal benefit of counterfactual data itself.

## Four training conditions

| Method | Addition |
| --- | --- |
| base | Absolute supervision on paired data, plus shared addressing and paraphrase consistency |
| behavior | base plus a 0.1 counterfactual behavioral-difference loss |
| hidden | behavior plus a 0.1 counterfactual hidden-difference loss |
| mixed | hidden, replacing the correct prefix of one FKL update every 4 continuation steps with a shared student trajectory |

The common objective averages full-vocabulary forward KL over A/B/P and adds 0.5 first-token correct-label CE, 0.2 address CE at actual prediction positions, 0.2 address CE across all training styles, and 0.05 first-position A/P output JS. All arms use paired values and equivalent paraphrases. The four-arm comparison therefore identifies increments from losses and trajectory recipes, not the isolated effect of having paired data. Warm-up uses base.

The teacher is the frozen original model with VeRA disabled and receives the branch's original observation text. The student receives only the question and reads the vector bank. Every teacher/student branch uses identical continuation token IDs. Prefixes are not reconstructed through decoding/re-tokenization, and truncated samples receive no artificial EOS.

Behavioral differences are compared only at **the first prediction position, before any answer token appears**. Define the two-candidate log-probability margin on each side and the effect as margin_A−margin_B. Match the teacher effect with SmoothL1. Clip the teacher target to ±10, leave the student unclipped, and use auxiliary weight 0.1. This auxiliary is active only when the teacher prefers the correct A/B candidate on each side and the effect is non-negligible. Record gate coverage and clipping rate; full-vocabulary first-token CE always remains active. A candidate-preference gate does not establish correctness over the whole vocabulary or complete answer, which require separate checks.

Hidden states are taken after the final RMSNorm. L2-normalize each state, then form Δh=h_A−h_B. The loss is `||Δh_student−stopgrad(Δh_teacher)||² / max(||Δh_teacher||², 1e-6)`. Pairs with teacher-difference norm below 1e-3 are excluded from this term's mean, with coverage reported. A zero student difference has loss 1 on eligible pairs. This constrains magnitude and direction rather than treating arbitrarily small changes in the right direction as success. The teacher difference also cannot simply be called a pure semantic direction.

During mixed's 128 student-trajectory updates, each target randomly samples one sequence from either its A or B bank at temperature 1, with at most 4 tokens. This common sequence supplies the FKL prefix for A/B/P. It is a mixture of two student policies, not a separate own-policy trajectory for each branch. First-token label CE, first-position counterfactual differences, and shared address objectives remain. Prefixes are replaced without adding updates. Length, termination, address-supervision states, and first-position weighting may also change, so the result measures the overall student-prefix recipe. Count actual tokens, sampling calls, and time separately; do not claim matched FLOPs.

## Evaluation after freezing

The same 64 new entities are evaluated in four quadrants: original observation/original question, original observation/new question, new observation/original question, and new observation/new question. For each target, independently build an A bank, replace its own record to obtain B, and paraphrase its own record to obtain P. Save base banks and exactly reconstructable patches, checking that other records and shared model parameters remain unchanged.

Each condition runs real A/B/P, shuffled A/B, forced-correct-value oracle A/B, and one empty-memory generation scored against both A/B. Apply the same shuffle permutation to both banks while keeping keys fixed. Oracle changes the top-k mixture distribution and is diagnostic only. The two diagonal quadrants additionally measure another unrelated entity before and after the update. Every target starts from its own A-bank copy, avoiding confounding from accumulated updates.

The primary metric is `PairedSwitchEM = mean(EM_A AND EM_B)`. Also report one-sided A/B EM, output-change rate, wrong→wrong changes, A/P joint EM and prediction agreement under paraphrase, correct-record R@1/R@4 and decode residency, and unrelated-question retention. The context-conditioned teacher is checked on A/B/P in the initial evaluation. Main tables use all examples; subsets where the teacher answers both sides correctly are reported with coverage, not as the only results.

Metric clarification: the runner's `changed_but_not_both_correct_rate` includes one-sided successes and is not strictly wrong→wrong. The summarizer separately recomputes `changed_both_wrong_rate` from raw predictions: normalized outputs change and both answers are wrong. `wrong_wrong_rate` also includes cases where both sides are wrong but the output is unchanged. This clarification changes neither training, raw outputs, nor the primary metric.

The initial anchored model and four final models use the same confirmation examples. Each method has one training seed. Paired bootstrap resamples entities; across the four quadrants, all conditions for an entity move together. Intervals do not capture training-seed or new structural-family uncertainty.

This is a limited-vocabulary mechanism experiment. If paired-switch accuracy remains near zero, preserve the full negative result rather than repeatedly trying losses on the same confirmation set to select a high score. Follow-ups need new validation data to study writer features, multilayer capacity, and genuine multi-token facts.
