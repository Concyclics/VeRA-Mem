# 训练模板方向消除：仅寻址的开发集诊断

训练模板均值投影改善了原查询及新观测格式的寻址，但**没有解决未见查询模板的泛化**。对原观测 bank，两个未见查询模板的 Recall@1 仅从 1/64、3/64 增至 2/64、4/64。这个结果支持继续研究表示与模板覆盖，不能作为端到端记忆泛化成功的证据。

执行时间为 2026-10-05 17:52 UTC。可复查的[完整汇总指标](results/generalization/address_probe.json)与[探针脚本](../scripts/probe_generalization_address.py)一并保存。原始特征缓存和探针权重留在本地工作区备份，不上传仓库。

## 对照协议

- 基座为冻结的 `Qwen/Qwen3-4B-Instruct-2507`，revision `cdbee75f17c01a7cc42f958dc650907174af0554`。使用第 20 层（零起始）`mlp.down_proj` 的最终提示 token 输入，维度 9,728。
- 训练使用 4,096 个实体、8 个查询模板和 4 个观测模板；开发集为 64 个独立实体。开发集包含原模板和两个未参与训练的模板。完整模板定义见 [augmentation_data.py](../src/vera_mem/augmentation_data.py)。确认集不参与任何统计拟合、打分或选择。
- 两组均训练 64 维 Q/K 编码器，初始化沿用真实 `StableVectorVeRA` 的 seed 42。固定 Adam 学习率 `1e-4`，400 步，每步 128 个互不重复实体，双向 InfoNCE 温度 0.1，梯度范数裁剪 1.0；每组共 51,200 对训练曝光。
- 实体抽样和 query/support 模板抽样使用独立且跨组匹配的 RNG；每个实体的 query 与 support 表述独立选择。同实体不同视图不互作负例。
- 只读取固定第 400 步的结果；不通过开发集选择 checkpoint、投影秩或超参数。投影只改变输入预处理，其余训练预算一致。
- **这是 400 步寻址预训练对照，不是主实验的 1,536 步 LM 训练结果。** 探针没有 value 写入、VeRA 残差、生成输出或逐 decode token 检索，不能把 Recall 直接当作回答 EM。

## 投影和能量分母

对 query、support 两个域分别处理。设训练实体为 \(i\)、训练模板为 \(t\)，先将特征归一化为

\[
u_{it}=\sqrt{d}\,x_{it}/\|x_{it}\|_2,\qquad
\mu_t=\frac1N\sum_i u_{it},\qquad
\mu=\frac1T\sum_t\mu_t.
\]

对模板均值差矩阵 \([\mu_t-\mu]_t\) 做 SVD，取非零方向组成正交列矩阵 \(U\)。相对奇异值阈值预先设为 `1e-5`，秩上限为模板数减一；实际 query 秩为 7，support 秩为 3。普通组使用 \(u-\mu\)，投影组使用 \((I-UU^\top)(u-\mu)\)，再按每条向量做 RMS 归一化，epsilon 为 `1e-6`。所有均值、方向均仅由训练特征估计，推理时不需要模板标签。

下表两列的共同分母为**该域全部训练实体和模板，在减去全局训练均值后的总平方能量**：

\[
E=\sum_{i,t}\|u_{it}-\mu\|_2^2.
\]

“模板均值能量”是 \(N\sum_t\|\mu_t-\mu\|_2^2/E\)；“投影删除能量”是 \(\sum_{i,t}\|U^\top(u_{it}-\mu)\|_2^2/E\)。后者还包含同一子空间内的实体变化，因此略大于前者。

| 域 | 模板均值能量 / E | 投影删除能量 / E | 投影秩 |
| --- | ---: | ---: | ---: |
| Query | 94.06% | 95.29% | 7 |
| Support | 79.94% | 81.51% | 3 |

这些比例不是原始未中心化激活的方差比例，也不是语义信息量的比例。删除高能量方向可能同时删除有用的实体信息；本探针只检验该操作对当前寻址任务的影响。

## 开发集结果

每个单元均以 **64 个事实**为分母。“记录卡”对应多行 field/value 格式；“前置约束”将回答要求或记录要求放在前面。表内是检索到正确事实记录的数量，而非答案词类别的命中数量。随机记录检索的期望 Recall@1 为 1/64，Recall@4 为 4/64。

| 查询格式 | 观测 bank 格式 | 普通组 R@1 | 投影组 R@1 | 普通组 R@4 | 投影组 R@4 |
| --- | --- | ---: | ---: | ---: | ---: |
| 原模板 | 原模板 | 47/64 | 64/64 | 63/64 | 64/64 |
| 原模板 | 未见记录卡 | 13/64 | 30/64 | 28/64 | 54/64 |
| 原模板 | 未见前置约束 | 6/64 | 27/64 | 20/64 | 48/64 |
| 未见记录卡 | 原模板 | 1/64 | 2/64 | 6/64 | 15/64 |
| 未见记录卡 | 未见记录卡 | 2/64 | 3/64 | 7/64 | 7/64 |
| 未见记录卡 | 未见前置约束 | 1/64 | 4/64 | 4/64 | 10/64 |
| 未见前置约束 | 原模板 | 3/64 | 4/64 | 10/64 | 10/64 |
| 未见前置约束 | 未见记录卡 | 2/64 | 4/64 | 5/64 | 6/64 |
| 未见前置约束 | 未见前置约束 | 1/64 | 3/64 | 4/64 | 5/64 |

原查询配合新观测的 R@1 从 20.31% / 9.38% 提高至 46.88% / 42.19%，说明训练模板方向确实干扰了部分寻址。新查询配合原观测的 R@1 仍只有 3.13% / 6.25%，双侧未见格式也只有 3–4/64 左右：该投影不足以解决主要泛化瓶颈。

一种尚未验证的解释是，最终提示位置的层输入含有很强的格式和回复风格成分；训练模板方向只能覆盖其中一部分，新的查询格式仍可能落在未覆盖方向。只有 64 个开发实体和一个初始化种子，本诊断不作显著性或普遍性结论，也不据此改写已冻结的确认实验。
